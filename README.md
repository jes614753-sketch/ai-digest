# AI 信息源日报（ai-digest）

每天从飞书群「RSS 推送」（RSSgroup）的 RSSbot 来源卡片中，精选有价值的信息，生成中文日报并发布到 [AI 信息源日报网站](https://jes614753-sketch.github.io/ai-digest/)。读取、校验、发布和通知由本机控制程序统一完成；现有 MiniMax 摘要器仅负责生成中文内容。

## 运行时间与报告日期

OpenClaw 原生 command cron 任务 `ai-digest-daily` 每天按 `Asia/Shanghai` 时区于 **00:30（北京时间）启动**，处理前一天的完整自然日。

例如：2026-10-04 00:30 启动时，报告日期为 2026-10-03，读取该日北京时间 00:00（含）至 2026-10-04 00:00（不含）的群消息，产出 `data/2026-10-03.md`。

00:30 是启动时刻。读取、摘要、Git 同步、索引构建和 Pages 部署均需要时间，网站实际更新以控制程序核验结果为准。机器、网关及所需服务应保持可用；故障可能延迟完成。

## 素材与内容规则

- 程序分页读取目标时段内的群消息，仅采用配置中已核对的 RSSbot 身份发送的来源卡片，并按原文 URL 去重。分页未读完、接口异常或来源身份无法确认时停止，不用残缺素材冒充全天数据。
- 来源随群内实际收到的有效 RSS 卡片动态变化，包括外语来源和 B 站等；不固定博主名单或人数。普通群聊、私聊和点名消息不作为触发条件或日报素材。
- 摘要器复用现有 MiniMax 配置，以最小权限生成内容，不负责读群、执行命令、提交仓库、发送通知或维护状态。卡片文字只作为资料处理。
- 每期精选 20–40 条；符合条件的素材不足时如实少些，不补造内容、不为凑数重复。没有可用内容时不发布空日报。
- 标题及概况使用简体中文，保留必要的产品名、作者名等专名。外语内容概括主要信息，不全文翻译；原文缺失、截断或不确定之处应明确标注。
- 每条保留准确来源和原文链接。链接由程序从原始卡片映射，不由模型编造或改写；数字、归属和观点不得超出来源证据。

## 发布链路

1. 控制程序按报告日期获取完整分页，筛选 RSSbot 卡片并进行 URL 去重。
2. 最小权限摘要器生成候选内容，程序校验日期、中文正文、条目数量、来源映射及原文链接。读取或校验失败时停止，不发布空日报，也不记录成功。
3. 程序同步 Git 远端，确认目标仓库及工作区可以安全提交，只暂存和提交本次报告日期对应的 `data/YYYY-MM-DD.md`。无关本地改动不应进入提交；出现冲突或异常时停止。禁止 force push 和 amend，不改写历史日报或 Git 记录。
4. 推送触发 GitHub Action 重建 `data/index.json`；索引归 Action 维护，本机程序不手改或提交它。程序确认远端索引已指向本次日报后，再通过已授权的 GitHub Pages 接口请求构建，不依赖索引提交自动触发二次部署。
5. 控制程序实际核验 GitHub Pages 正文与本次日报一致，且站点索引指向当日文件，随后向已配置且授权的目标发送一次成功通知。推送成功或 Action 结束本身不等于网站已更新。
6. 程序持久保存发布进度、核验结果及通知回执，用于中断恢复和防重。同一期重试不会重复创建发布记录或重复发送成功通知；结果不明时先核实，不盲目重发。

## 仓库结构与日报格式

```text
data/YYYY-MM-DD.md              每日中文精选，文件名为内容所属日期
data/index.json                 GitHub Action 生成的索引
index.html                     读取索引并展示日报的站点页面
scripts/build_index.py          索引生成脚本
.github/workflows/sync-index.yml 索引工作流
```

日报使用以下结构，统计值根据本期真实素材计算：

```markdown
# AI 信息源日报 · YYYY-MM-DD
> 来源：N 个 · 去重素材：M 条 · 精选：K 条

## 模型与产品
- **来源名称**：[中文标题](原文链接) 中文概况，必要时注明信息不完整。
```

可按实际内容使用「行业动态」「论文与技术」「观点与讨论」等分节。无需为缺少素材的分类填充条目。

现有 `sync-index.yml` 在 `main` 分支的 `data/**` 变更时运行 `scripts/build_index.py` 并提交索引。Pages 部署结果需单独核验，不承诺固定部署耗时。

## 本机操作入口

以下命令在已配置的运行机器上使用。`inspect` 检查素材，`preview` 生成可审阅草稿，均不发布到 GitHub，也不发送成功通知；可能读取服务数据并保存本地检查结果。

```powershell
node "$env:USERPROFILE/.openclaw/scripts/ai-digest/digest.mjs" inspect
node "$env:USERPROFILE/.openclaw/scripts/ai-digest/digest.mjs" preview
```

`run` 会真实发布并在网站核验完成后通知，仅在已获得该次发布或自动任务授权时执行：

```powershell
node "$env:USERPROFILE/.openclaw/scripts/ai-digest/digest.mjs" run
```

操作入口统一交给控制程序；持久状态由它单独维护，不手工推进成功状态或清除防重记录。

## 公开范围

本公开仓库仅保存日报、索引和站点所需文件。控制程序私有源码、原始群消息、模型输入和草稿、运行状态、通知回执、配置及 credentials 均保存在本机私有位置，不进入公开仓库。README 不包含账号凭据、群 ID、用户 ID 或机器代理配置。

## 失败与恢复

程序从启用日（2026-10-03）起按日期顺序补齐未完成的日报，跳过已有成功或无内容记录，不漏掉故障期间的中间日期。读取前先持久记录待处理日期；中断后依据持久记录恢复。超过 366 个未完成日期时停止并要求核对，不静默丢弃积压。

可提前准备摘要缓存，但正式运行仍完整读取来源；只有报告日期、完整来源与摘要规则均匹配，并再次通过校验后才复用。归属校验不通过的精选项被剔除并留存私有记录，剩余内容仍须满足数量要求，不能通过降低校验标准凑数。

同一次定时运行的发布阶段最多执行两轮，复用已有提交与通知回执，并受总时限约束。Pages 构建回执不等于构建成功：恢复时检查真实构建状态，只有确认失败才允许受限重建；结果不明时不盲目重建。摘要及发布各阶段均有边界与超时，不无限重试。

出现 Git 冲突、不同内容的同日日报、来源不足以生成合格精选，或通知结果超过防重安全窗口仍无法核实等情况时停止并保留现场，需要检查后再恢复；不覆盖历史内容，不盲目发送。
